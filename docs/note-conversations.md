# 私人 AI 对话

Q4 附加阶段为每篇笔记提供一个持久对话线程，复用账号当前模型服务。需要联网及运行中的 worker；模型费用由配置的供应商收取。

## 数据与上下文

- 每次提问保存问题，后台生成回答；原文、摘要、标注和评论不被修改。单篇同一时间只处理一个问题。
- 只发送标题、原始正文、最近最多 10 轮已完成问答及当前问题，不包含私人标注、评论、Cookie、原始 HTML 或其他笔记。正文优先使用有序内容块文本。
- 正文按模型设置的文本预算截断，最多 32000 UTF-8 字节；历史每条最多 4000 字节、合计最多 16000 字节，优先保留最近的完整问答。因此长问答可能少于 10 轮。当前问题最多 4000 字符，回答最多 24000 字符，生成上限 2000 tokens。
- 模型收到截断标记和明确的资料边界，但回答仍需自行核对原文；没有联网搜索或工具执行能力。
- 对话不进入公开分享、单篇 Markdown/HTML/PDF 导出、笔记离线缓存或离线写队列。资料库 ZIP/JSON 与自动备份保留已完成问答，Markdown 资料库附带“私人 AI 对话”。未完成或失败的问题、任务状态及模型凭据不备份。
- 恢复时重新映射笔记与消息 ID，保留轮次和时间；旧备份缺少对话字段时视为空。恢复的问答可作为后续提问上下文。删除笔记同时删除对话及任务。

## API 与运行机制

- `GET /api/v1/notes/{id}/conversations`：最新 20 轮，包含按时间排列的 `turns`、`latest_job` 与 `next_before`；用 `before` 向前翻页，`limit` 为 1–50 轮。
- `POST /api/v1/notes/{id}/conversations`：`question` 与客户端稳定生成的 `request_key`，返回 HTTP 202 和任务状态；客户端轮询历史获取回答。
- `POST /api/v1/conversation-jobs/{id}/retry`：仅重试最新的失败问题。也可跳过失败问题继续提问，失败问题不进入模型上下文。

所有接口、仓储和执行任务均限定账号；读取他人笔记/任务返回 404。共享数据库按账号限制提问与重试合计每分钟 10 次。重复提交相同问题和请求键返回原任务；同键不同问题/笔记拒绝，其他并发提问返回 409。

迁移 `0021_note_conversations` 新增消息表和持久任务表，兼容 SQLite / PostgreSQL；回滚删除对话数据，保留笔记。先提交数据库再入队，worker 每分钟恢复遗漏分发及过期租约；执行租约 10 分钟，失败在 30/120/480 秒后重试，最多四次。无密钥立即失败，日志与错误只含通用提示，不回显模型响应或凭据。过期执行结果不能覆盖新执行；网络中断后的恢复可能再次调用模型，供应商侧不保证只计费一次。
