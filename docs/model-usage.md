# 模型月度调用限额

Q4 成本控制补充提供按账号的模型请求次数限额。默认不限；`0` 暂停新的模型调用，正整数限制每月次数（最多 1000000）。按 UTC 自然月统计，下月 1 日 00:00 UTC 开始新周期；中国标准时间为当日 08:00。升级前的历史调用无法回填。

## 计数与恢复

- 摘要及随同生成的评论评分/精华算一次请求；格式兼容重试、后台重试分别计数。单独重新摘要、多轮对话的每次生成、笔记与搜索查询嵌入共用一个账号额度。
- 每次尝试在发往模型之前提交计数。失败、超时及异常返回仍计数；进程在计数后崩溃可能计入一次未发送的请求，不退款，以避免不确定请求绕过限额。数量不是供应商账单，不等于 token 用量或金额预算；金额上限仍需在供应商侧配置。
- 无密钥、被限额拦截、读取缓存向量、关键词搜索、查询模型列表、纯索引扫描及重复任务未执行模型时不计数。关闭限额期间也持续计数，重新启用不会重置用量。
- 达到上限后，新采集保留原文和评论并显示未生成摘要；重新摘要保留旧内容；对话保留问题和历史；语义搜索显示限额提示并回退关键词结果。额度失败停止自动重试。
- 调高/取消限额或进入下月后，可重试摘要/回答、点击“补齐索引 / 重试失败”。失败查询最多缓存 10 分钟；补齐索引同时清除失败查询，可立即重新搜索。调低限额不能撤销已获准的在途请求。

## 接口与存储

- `GET /api/v1/settings/model-usage`：返回当前 UTC 月份 `month`、下次重置时间 `resets_at`、`monthly_limit`、已用 `calls` 和 `remaining`（不限时为 `null`）。
- `PUT /api/v1/settings/model-usage`：请求 `{"monthly_limit": 100}`；`null` 表示不限，`0` 表示暂停。鉴权后仅能访问本账号，不接受客户端传入用量。
- 迁移 `0022_model_usage` 新增 `user_settings.monthly_model_limit` 和按账号/月唯一的计数表。SQLite/PostgreSQL 在短事务内锁定账号设置并保留一次额度；所有 API/worker 进程共用数据库，在网络调用前释放锁。重启及更换模型不会清零。
- 计数不保存正文、问题、模型响应或凭据；不进入公开分享、离线缓存及资料库备份。备份恢复不改变目标账号限额/用量，删除账号级联删除计数。限额是账号自主管理功能，不是管理员强制账单策略。
- 回滚迁移删除限额和用量，笔记与对话保留；重新升级从不限/零计数开始。正常升级不回填过去的调用。
