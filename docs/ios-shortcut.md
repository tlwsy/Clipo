# iOS Shortcut 配置

iOS 不支持 Web Share Target，PWA 无法出现在系统分享面板里。Shortcut 是 iOS 上的录入方案：它接收分享内容，直接向 Clipo API 发一个 POST 请求，不打开浏览器。

流程是静默的。分享 → 点 Clipo → 通知提示已保存，全程一次点击，之后可以完全不管。内容整理在服务端异步完成。

## 前置准备

1. Clipo 已部署且可从手机网络访问。
2. 服务启用 HTTPS。明文 HTTP 会让 API Token 在网络中暴露。
3. 在网页端 设置 → API Token → 新建，命名为 `ios-shortcut`，复制明文 Token。

## 导入与配置

1. 在 iPhone 上打开仓库 `shortcuts/clipo.shortcut`（或从 Releases 下载）。
2. 快捷指令 App 会提示导入，确认后打开该指令编辑。
3. 修改两处文本变量：
   - `SERVER`：你的地址，例如 `https://clipo.example.com`
   - `TOKEN`：刚才复制的 API Token
4. 保存。

首次运行时 iOS 会询问是否允许该指令访问网络，选允许。

## 手动搭建（不想用现成文件）

快捷指令 App → 新建指令，按顺序添加：

1. **接收**：在指令详情里开启"在共享表单中显示"，接受类型勾选 URL 与文本。
2. **文本**：值为 `https://clipo.example.com`，重命名为 `SERVER`。
3. **文本**：值为你的 API Token，重命名为 `TOKEN`。
4. **获取 URL 内容**：
   - URL：`SERVER` 拼接 `/api/v1/captures`
   - 方法：`POST`
   - 请求头：`X-Clipo-Token` = `TOKEN`，`Content-Type` = `application/json`
   - 请求体：JSON，字段 `url` 取"快捷指令输入"
5. **显示通知**：标题"已保存到 Clipo"，内容可取上一步响应里的 `status`。

请求体形如：

```json
{ "url": "https://www.xiaohongshu.com/explore/xxxx" }
```

服务端返回 202 与任务信息：

```json
{ "job_id": "j_01H...", "status": "queued", "note_id": null, "cached": false }
```

通知弹出只代表服务端已接受任务。抓取与摘要还需数十秒，结果在网页端的保存队列页可见。

## 小红书的两点提醒

小红书分享出来的通常是带跳转的短链，Clipo 服务端会自行解析重定向，不需要你在 Shortcut 里处理。

服务端抓取小红书需要登录态。移动端分享走的是服务端路径，所以要在网页端 设置 → 平台 Cookie 里填好小红书 Cookie（获取方式见配置参考）。桌面场景用浏览器扩展则不需要这一步。Cookie 过期后任务会失败并明确提示需要更新。

## 让它更顺手

把指令加到主屏幕，可以直接粘贴链接保存，适合从别处复制来的链接。

在"快捷指令"的自动化里也可以配合"共享"触发，但一般没必要，分享面板里点一次已经足够快。

想在保存时顺手加标签，可在第 4 步前插入"要求输入"，把结果放进请求体的 `tags` 字段。默认不加，是为了保持一次点击完成。

## 排障

| 现象 | 处理 |
|------|------|
| 提示 401 | Token 填错或已撤销，重新生成并更新指令 |
| 提示无法连接 | 手机不在可访问服务的网络中；确认域名解析与端口开放 |
| 证书错误 | 自签证书需在 iOS 设置中安装并信任描述文件，建议直接用 Let's Encrypt |
| 通知显示成功但网页端没有笔记 | 打开保存队列页看任务状态与失败原因 |
| 分享面板里找不到指令 | 检查指令详情中"在共享表单中显示"是否开启，接受类型是否包含 URL |
