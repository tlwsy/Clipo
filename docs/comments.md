# 评论采集与 AI 精华

评论与回复共享设置中的采集上限（0–100，默认 100；0 关闭）。保存来源 ID 与父评论 ID，重复 ID 去重；分页有请求次数、循环游标和时间限制，因此不承诺取得整篇帖子的全部讨论。

- 小红书：读取页面内嵌回复；配置完整 Cookie 且链接带访问参数时，通过签名接口补抓楼中楼。
- B 站：读取内嵌回复并补抓楼中楼分页。
- YouTube：读取内嵌回复和回复 continuation，支持已有两代评论结构。
- 小黑盒：保留接口每层返回的全部评论及内嵌回复；尚未接入未展开回复的独立分页。
- 浏览器扩展：采集已加载、可见的回复。未展开的楼中楼可能缺失，可先展开后保存。

AI 在同一次摘要请求中先评分，再整合达到配置阈值的评论，合并重复观点、保留不同意见。后端校验精华引用，丢弃引用不存在、未评分或低分评论的条目。评分与整合仍受模型质量影响；回复的父评论仅作为理解上下文，不自动作为优质证据。

详情页先展示 AI 评论精华，来源链接跳转到具体评论；优质评论按讨论关系分组并显示回复对象。低分评论直接隐藏，不从数据库删除；未评分评论折叠展示，避免把模型失败、候选数量或输入长度限制误当作低质量。公开分享页也展示精华并隐藏非优质评论。JSON 备份保留完整评论、回复关系、评分和精华；Markdown 导出明确标注包含隐藏的原始评论。

旧笔记不会自动请求平台或模型。重新生成摘要可为已保存评论生成新评分与精华；若旧笔记没有采集回复，需要重新保存原链接或从扩展保存。旧提取缓存会因版本变化失效。模型未返回精华时保留摘要和评分，界面提示尚未生成。

数据库迁移 `0016_comment_threads` 增加可空的评论关系字段与默认空的精华列表，不删除旧内容、不重写 Cookie。回滚该迁移会移除新增关系和精华字段，原评论、评分与 Cookie 保留。Docker 升级的数据卷和加密主密钥要求见[部署指南](deployment.md)。
